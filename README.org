* tatort-sorter

This Python script parses the file names of the current directory and
matches them against the long table from [[https://de.wikipedia.org/wiki/Liste_der_Tatort-Folgen][Liste der Tatort-Folgen –
Wikipedia]]. The list is dynamically loaded from the web.

Two input file name patterns are supported:

- *MediathekView downloads* are matched by the "Titel" from Wikipedia
  (see [[*Why][Why]]):
  : 2021-05-16T20.15.00 ORF - Tatort - Wo ist Mike -- highquality.mp4
- *Web downloads* are matched by season and episode, and the title is
  checked against Wikipedia (see [[*Web downloads][Web downloads]]):
  : Tatort S2026E18 Die letzten Menschen von Koeln 1080p ARD WEB-DL AAC2 0 H 264-NTb[EZTVx.to].mkv

If a match is found, the file then gets moved to a sub-directory
according to the name of the "Ermittler". Furthermore, the file gets
renamed according to this pattern:

: YYYY-MM-DD Tatort <Folge> S<YYYY>E<xx> - <Ermittler> <Fall> - <Titel>.<extension>

The date is the date of the "Erstausstrahlung". The season =S<YYYY>=
is the year of the Erstausstrahlung, the episode =E<xx>= is the
position of the episode within that year (as used by web downloads).
Here is an example file name from the directory "Ballauf und Schenk":

: 2026-09-20 Tatort 1340 S2026E18 - Ballauf und Schenk 96 - Die letzten Menschen von Köln.mkv

If you are using [[https://github.com/novoid/filetags][filetags]], they will be preserved, except for the
tag "highquality" which gets removed. Here is an example with the tag
"karl" being re-used in the resulting file name:

: 2011-08-28 Tatort 807 S2011E22 - Eisner 26 - Lohn der Arbeit -- karl.mp4

- *Target group*: users who are able to use command line tools and who
  are not afraid of Python scripts
- Hosted on github: https://github.com/novoid/

** Why

I'm downloading [[https://de.wikipedia.org/wiki/Tatort_(Fernsehreihe)][Tatort]] episodes [[https://karl-voit.at/mediathekview/][via the MediathekView software]].

With dozens of episodes in a folder, you don't have any idea on
temporal order or who are the Ermittler. 

A typical set of files downloaded via MediathekView and renamed
according to [[https://karl-voit.at/mediathekview/][my usual download process]] looks like that:

: 2021-05-16T20.15.00 ORF - Tatort - Wo ist Mike -- highquality.mp4
: 2021-05-09T20.15.00 ORF - Tatort - Verschwörung -- highquality.mp4
: 2021-05-02T20.15.12 ORF - Tatort - Rhythm and Love -- highquality.mp4
: 2021-04-25T20.15.12 ORF - Tatort - Was wir erben -- highquality.mp4
: 2021-04-18T20.15.12 ORF - Tatort - Macht der Familie -- highquality.mp4
: 2021-04-11T20.15.05 ORF - Tatort - Der böse König -- highquality.mp4
: 2019-05-12T20.15.00 ORF - Tatort - Das Monster von Kassel -- highquality.mp4

After applying this script, the files are moved to sub-directories and
renamed like that:

: Voss, Ringelhahn, Goldwasser, Fleischer und Schatz/2021-05-16 Tatort 1168 S2021E18 - Voss, Ringelhahn, Goldwasser, Fleischer und Schatz 7 - Wo ist Mike?.mp4
: Eisner und Fellner/2021-05-09 Tatort 1167 S2021E17 - Eisner und Fellner 51 - Verschwörung.mp4
: Thiel und Boerne/2021-05-02 Tatort 1166 S2021E16 - Thiel und Boerne 39 - Rhythm and Love.mp4
: Tobler und Berg/2021-04-25 Tatort 1165 S2021E15 - Tobler und Berg 7 - Was wir erben.mp4
: Falke und Grosz/2021-04-18 Tatort 1164 S2021E14 - Falke und Grosz 15 - Macht der Familie.mp4
: Odenthal und Stern/2021-04-11 Tatort 1163 S2021E13 - Odenthal und Stern 74 - Der böse König.mp4
: Faber, Bönisch, Dalay und Pawlak/2020-02-02 Tatort 1119 S2020E05 - Faber, Bönisch, Dalay und Pawlak 16 - Monster.mp4

Notice the potentially different dates. The downloaded files do have the
time-stamp from the broadcast whereas the renamed files do have the
date of their first broadcast ("Erstausstrahlung"). In my example
above, the last file looks like it was initially broadcast on
2020-02-02, which is actually a wrong association (see [[*Warning: Wrong associations][Wrong
associations]]).

** Web downloads

Besides MediathekView downloads, the script also handles web downloads
which contain season and episode in their file names:

: Tatort S2026E18 Die letzten Menschen von Koeln 1080p ARD WEB-DL AAC2 0 H 264-NTb[EZTVx.to].mkv

These files are matched via =S2026E18= and the title is checked
against the Wikipedia title (tolerating =ae/oe/ue/ss= instead of
umlauts and missing punctuation). If the titles differ, you are asked
for confirmation. Release meta-information starting with the
resolution (=1080p=, =720p=, =2160p=, ...) or source (=WEB-DL=,
=WEBRip=, =HDTV=, ...) is removed. The title is taken from Wikipedia
and the file extension is kept:

: Ballauf und Schenk/2026-09-20 Tatort 1340 S2026E18 - Ballauf und Schenk 96 - Die letzten Menschen von Köln.mkv

** Double downloads

Before moving a file, all sub-directories are checked for already
sorted files with the same Tatort number (the number after "Tatort"),
e.g., =2026-09-20 Tatort 1340 - Ballauf und Schenk 96 - Die letzten
Menschen von Köln -- highquality.mp4= in the old pattern without
=S<YYYY>E<xx>=. This is independent of the file name pattern, the
spelling of the title, the Ermittler directory, filetags, or the file
extension. Such a file is reported as a potential double and you are
asked: "Move it (m), delete it (d) or skip it (s)?". Deleting removes
the new download, not the already sorted file. With =--simulate=,
nothing gets moved or deleted. Files with the exact same target name
are never overwritten.

** Already watched episodes (history)

If you delete episodes after watching them, the check for double
downloads above can't help when the same episode gets downloaded once
more years later (e.g., because of a re-transmission). Therefore, the
script keeps a history file of all Tatort numbers it has ever seen:

- every file it sorts and
- every already sorted file it finds in the sub-directories on each
  run, so episodes sorted manually or before the history existed are
  recorded as well.

When a new download has the same Tatort number as an entry from the
history but is not on disk any more, you get a warning with the date
and the old file name, and the same question: "Move it (m), delete it
(d) or skip it (s)?".

The history file is located at the first of:

1. =--history PATH=
2. environment variable =TATORT_SORTER_HISTORY= (e.g., to put it in a
   synchronized folder for multiple computers)
3. =$XDG_STATE_HOME/tatort-sorter/seen_episodes.txt=
4. =~/.local/state/tatort-sorter/seen_episodes.txt=

It is a plain text file with tab-separated lines (Folge, date
recorded, source, file name):

: 1340	2026-11-08	sorted	Ballauf und Schenk/2026-09-20 Tatort 1340 S2026E18 - Ballauf und Schenk 96 - Die letzten Menschen von Köln.mkv
: 905	2026-11-08	scanned	Ballauf und Schenk/2014-03-23 Tatort 905 - Ballauf und Schenk 59 - Der Fall Reinhardt -- highquality.mp4
: 1101

You may edit it manually: a line with just a Tatort number is a valid
entry, e.g., for episodes you have watched on TV or deleted before the
history existed. Lines starting with =#= are comments. With
=--simulate=, the history file is read but never written.

Please note:
- A history entry means "was sorted or found before", not necessarily
  "was watched".
- Episodes deleted before the first run with the history are unknown
  unless you add them manually.
- A wrong association (see [[*Warning: Wrong associations][Wrong associations]]) results in a wrong
  history entry. Check the file name shown in the warning and remove
  wrong lines from the history file.

** Warning: Wrong associations

This affects MediathekView downloads only: web downloads are matched
by =S<YYYY>E<xx>= and you are asked for confirmation if their title
differs from the Wikipedia title.

The list of Tatort episodes is processed in reverse order with the
newest episodes first. If there is a general episode title like
"Mord", /any/ file name containing "Mord" is a match even though the
file name is "Das ist kein Mord hier.mp4". This might result in *wrong
associations* and therefore wrong sub-directories as well as wrong file
names. So please do check the screen output and revert wrong matches
manually. Here is a real example of a wrong match:

: INFO     Moving file "2019-05-12T20.15.00 ORF - Tatort - Tatort_ Das Monster von Kassel -- highquality.mp4" → 
:      Faber, Bönisch, Dalay und Pawlak/2020-02-02 Tatort 1119 S2020E05 - Faber, Bönisch, Dalay und Pawlak 16 - Monster.mp4

The file should have been:
: Janneke und Brix/2019-05-12 Tatort 1094 S2019E17 - Janneke und Brix 9 - Das Monster von Kassel.mp4

For additional confidence, the script prints out a warning if the
dates differ. You need to check manually.

This is a correct association although the dates differ:

: INFO     Moving file "2020-11-07T22.35.00 ORF - Tatort - Tatort  Der Mann, der lügt -- highquality.mp4" →
:     Lannert und Bootz/2018-11-04 Tatort 1071 S2018E31 - Lannert und Bootz 22 - Der Mann, der lügt.mp4

** Simulate first!

I would recommend you to *use the command line switch "--simulate"
first* so that you see what would happen, before you actually modify
files! Double downloads and the history are checked, but nothing gets
moved, deleted, or written to the history file.

: uv --project /path/to/Tatort-sorter run tatort-sorter --simulate

** Usage

: uv --project /path/to/Tatort-sorter run tatort-sorter
... does its magic in the current directory of execution

# #+BEGIN_SRC sh :results output :wrap src
# uv --project /path/to/Tatort-sorter run tatort-sorter -h
# #+END_SRC

#+begin_src
usage: tatort-sorter [-h] [-s] [--history PATH] [-v] [-q] [--version]

This script moves episodes of "Tatort" into sub-folders according to the names of the Ermittler.

options:
  -h, --help      show this help message and exit
  -s, --simulate  Just print what's being done, do not move or delete files,
                  create directories, or write the history file
  --history PATH  History file of already sorted/seen Tatort numbers (default:
                  $TATORT_SORTER_HISTORY or
                  $XDG_STATE_HOME/tatort-sorter/seen_episodes.txt or
                  ~/.local/state/tatort-sorter/seen_episodes.txt)
  -v, --verbose   Enable verbose mode
  -q, --quiet     Enable quiet mode
  --version       Display version and exit

** Installation

Install via [[https://docs.astral.sh/uv/][uv]]:

: uv tool install --from git+https://github.com/novoid/Tatort-sorter tatort-sorter

Or clone the repository and run directly:

: git clone https://github.com/novoid/Tatort-sorter.git
: cd /path/to/your/tatort/files
: uv --project /path/to/Tatort-sorter run tatort-sorter --simulate
